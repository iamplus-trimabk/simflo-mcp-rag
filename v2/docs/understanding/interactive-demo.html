CLI-First Architecture Overview

This is my personal understanding of building a practical RAG system using CLI-first principles. Instead of complex distributed systems, I built something that works like familiar Unix commands.

00 - Registry System

Purpose: Foundation - Manages multiple RAG databases with registry-based organization.

What It Does

  • Manages independent registries (shadcn, gluestack, community)
  • Each registry has its own vector database and source files
  • Provides CLI commands for database management
  • Organizes content by extractor type (components, hooks, blocks)

Key Commands

rag_registry list --format json
rag_registry info --name shadcn --format json
rag_registry search --query "button" --limit 10 --format json
rag_registry status --format json
rag_registry clean-db --registry shadcn --format json
rag_registry rebuild-db --registry shadcn --format json

Why This Structure Works

Each registry is completely independent - problems in one don't affect others. I can add new registries easily without touching existing ones.

Integration Pattern

AI assistants can call these CLI commands directly and get structured JSON responses with component matches, relevance scores, and installation information.

02 - RAG Builder

Purpose: Orchestration - Pipeline construction and management.

What It Does

  • Builds and manages RAG pipelines
  • Coordinates between different components
  • Provides status monitoring and health checks
  • Manages pipeline profiles and configurations
  • Handles pipeline construction from various data sources

Pipeline Commands

rag_builder status
rag_builder list-profiles
rag_builder check
rag_builder build --config config.json

Why It's Important

This component orchestrates the entire RAG construction process, ensuring that data flows properly from content collection through extraction to final vector database creation.

Integration Points

Works with all other components - coordinates extractors, manages registry databases, and provides the foundation for MCP server searches.

04 - Extractors

Purpose: Content Processing - 11 specialized extractors for different sources.

What It Does

  • Provides CLI interface for 11 specialized extractors
  • Extracts content from various component libraries
  • Processes different content types (components, hooks, blocks)
  • Orchestrates extraction operations across multiple sources
  • Manages extraction status and progress tracking

Extraction Commands

extractors list-extractors
extractors run-extractor shadcn
extractors run-all-extractors
extractors status

Available Extractors

  • shadcn: Shadcn components extraction
  • shadcn_hooks: Shadcn hooks extraction
  • shadcn_components: Shadcn components specific extraction
  • shadcn_blocks: Shadcn blocks extraction
  • gluestack: Gluestack components extraction
  • npm_hooks: NPM hooks extraction
  • community: Community components extraction
  • documentation: Documentation extraction

Why This Approach Works

CLI wrapper around existing extraction modules provides orchestration without modifying the underlying extraction logic. Each extractor can be run independently or as part of a batch operation.
