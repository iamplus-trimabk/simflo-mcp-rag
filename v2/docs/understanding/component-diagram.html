CLI-First Architecture Overview

This architecture demonstrates how CLI-first design can create a maintainable, scalable RAG system. Each component communicates through standardized JSON responses over direct CLI calls.

Key Principles

  • Direct Communication: Components call each other directly via CLI, no HTTP overhead
  • JSON Standardization: All components return consistent JSON format
  • Independent Registries: Each component library has its own isolated database
  • CLI Testing: Simple, reliable testing through CLI command validation
  • Command Aliases: Maintainable interface through centralized alias system

00 - Registry System Details

Purpose: Foundation layer that manages independent RAG databases for different component libraries.

Key Features

  • Registry-based organization (shadcn, gluestack, community)
  • Independent vector databases and file storage
  • CLI commands for database management
  • Content organized by extractor type
rag_registry list --format json
rag_registry search --query "button" --limit 10 --format json
rag_registry info --name shadcn --format json
rag_registry rebuild-db --registry shadcn --format json

Integration Points

Provides the foundation for all other components - stores processed content from extractors, serves search queries for MCP server, and receives orchestration commands from RAG builder.

01 - MCP Server Details

Purpose: Primary interface for AI assistants, providing 12 CLI commands for component discovery and interaction.

Key Features

  • Direct CLI interface (no HTTP overhead)
  • 12 comprehensive commands for AI integration
  • Natural language component search
  • Platform context management
  • Structured JSON responses
mcp_server search "modal dialog" --limit 5 --platform reactjs
mcp_server get-component button --registry shadcn
mcp_server set-context reactjs --session-id abc123
mcp_server list-registries

Integration Points

Direct interface for AI assistants - queries registry system for components, manages context for intelligent recommendations, and provides the primary user interface for the RAG system.

02 - RAG Builder Details

Purpose: Orchestration layer that coordinates pipeline construction and manages system-wide operations.

Key Features

  • Pipeline orchestration and coordination
  • System status monitoring
  • Configuration management
  • Health checks and validation
  • Component lifecycle management
rag_builder status
rag_builder list-profiles
rag_builder check
rag_builder build --config config.json

Integration Points

Central coordinator - triggers content collection, manages extractors, updates registries, and provides system-wide status information for monitoring and maintenance.

03 - Content Collection Details

Purpose: Input layer that discovers new component libraries and acquires content from various sources.

Key Features

  • Multi-source discovery (GitHub, npm, documentation)
  • Natural language source search
  • Content fetching and organization
  • Source metadata extraction
  • Quality evaluation and filtering
content_collection discover --query "react components" --source-type github --limit 10
content_collection fetch --sources-file sources.json
content_collection list-source-types
content_collection status

Integration Points

Feeds the content pipeline - discovers new sources for extractors to process, provides source metadata to RAG builder, and ensures continuous content updates for the system.

04 - Extractors Details

Purpose: Processing layer with 11 specialized extractors that transform raw content into structured, searchable data.

Key Features

  • 11 specialized extractors for different content types
  • CLI orchestration interface
  • Batch processing capabilities
  • Error handling and recovery
  • Metadata generation and organization
extractors list-extractors
extractors run-extractor shadcn
extractors run-all-extractors
extractors status

Available Extractors

  • shadcn, shadcn_hooks, shadcn_components, shadcn_blocks
  • gluestack, npm_hooks, community
  • documentation, examples, assets, metadata

Integration Points

Content transformation engine - processes content discovered by content collection, structures it for registry storage, and provides the processed data that MCP server searches through.
